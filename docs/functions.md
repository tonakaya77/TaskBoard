# TaskBoard 機能設計

[要件定義書](requirements.md) の機能に関する詳細をまとめる。

## 1. 機能一覧

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | ログイン・ログアウト | メールアドレスとパスワードでログインする。アカウントは初期データで用意する |
| F-02 | プロジェクト管理 | プロジェクトを複数作成できる。作成・名前と色の変更・削除ができる。必須の入力はタイトルだけ。色は基本カラー（赤・オレンジ・黄・緑・青・紫・ピンク・グレーの8色）から選ぶか、カラーコードで指定する |
| F-03 | ステータス管理 | プロジェクトごとにステータス（列）を持つ。初期値は「未着手 / 進行中 / 確認中 / 完了」。追加・名前変更・並び替え・削除ができる。タスクが残っているステータス、初期ステータス（未着手）、完了ステータスは削除できない |
| F-04 | タスク管理 | タスクの作成・編集・削除。項目はタイトル（必須）、説明、期限、ステータス |
| F-05 | ステータス変更・並び替え | ボード上でカードをドラッグ＆ドロップして別の列へ移す。同じ列の中でもカードの順番を入れ替えられる |
| F-06 | サブタスク | タスク詳細の中で、追加・完了切り替え・並び替え・文言の修正ができる。ボードとダッシュボードのカードに、完了した数 / 全体の数を表示する |
| F-07 | 期限アラート | 期限の3日前〜1日前は黄色、当日と期限超過は赤で表示する。期限当日のときは「期限当日」、期限超過のときは「期限超過」「見直しをしてください」と表示する。「今日」は朝4時に切り替わる |
| F-08 | ダッシュボード | 左に「今日やるタスク」、右に「タスク一覧」を表示する。タスク一覧には、全プロジェクトの完了以外のタスクを、期限が近い順に表示する。一覧から今日やるタスクへ移せる。完了にしたタスクは、今日やるタスクからすぐ外れる |
| F-09 | カレンダー | 月表示のカレンダーで、期限日の位置にタスクを表示する。完了したタスクはグレーで表示する。今日の日付には印をつける。表示だけで編集はしない。クリックするとタスク詳細を開く |
| F-10 | タスク詳細 | 表示と編集の画面を分ける |

## 2. 機能詳細

### F-01 ログイン・ログアウト
- メールアドレスとパスワードでログインする。アカウントは初期データで用意する
- 失敗したときは「メールアドレスまたはパスワードが正しくありません」と表示する。どちらが間違っているかは伝えない
- ログインしたままにする。最後の操作から7日間操作がなければ、自動でログアウトする（セキュリティの観点で、あとで見直す可能性がある）
- ログインしていない状態でほかの画面を開くと、ログイン画面に移る

### F-02 プロジェクト管理
- プロジェクトは複数作れる。タイトルは必須で、30文字まで
- 作成したときの色は、基本の8色（赤→オレンジ→黄→緑→青→紫→ピンク→グレー）から、まだ使われていない色を順番に割り当てる。8色とも使われているときは、赤から繰り返す
- 色は、基本カラーから選ぶか、カラーコード（`#` ＋ 16進数6桁）で変えられる
- 基本カラーのカラーコードは、赤 `#EF4444`、オレンジ `#F97316`、黄 `#EAB308`、緑 `#22C55E`、青 `#3B82F6`、紫 `#A855F7`、ピンク `#EC4899`、グレー `#6B7280`
- サイドメニューには、作成した順（古い順）に並べる
- 削除するときは確認を出す。中のステータス・タスク・サブタスクもまとめて削除する

### F-03 ステータス管理
- プロジェクトを作ると、4つ（未着手 / 進行中 / 確認中 / 完了）を自動で作る。「未着手」は初期ステータス、「完了」は完了ステータスとして、それぞれIDで記録する
- 初期ステータスと完了ステータスは、IDで判断するので、名前を変えても役割は変わらない
- 追加したステータスは一番後ろに入る。名前は必須で、20文字まで
- 名前の変更と、ドラッグでの並び替えができる
- ステータスの追加・名前の変更・並び替え・削除は、プロジェクト設定の「保存」を押したときにまとめて保存する。「キャンセル」なら、すべて取り消す
- タスクが残っているステータス、初期ステータス、完了ステータスは削除できない

### F-04 タスク管理
- タイトルは必須で50文字まで、説明は1000文字まで、期限はなくてもよい
- 作成するときのステータスの初期値は、初期ステータス（未着手）
- 新しいタスクは、列の一番下に入る
- 削除するときは確認を出す。サブタスクもまとめて削除する

### F-05 ステータス変更・並び替え
- ドラッグ＆ドロップで、別の列へ移したり、同じ列の中で並べ替えたりできる
- 保存に失敗したら、元の位置に戻してエラーを表示する
- スマホでは、タスク編集でステータスを変える。そのときは、移した先の列の一番下に入る。スマホでは、同じ列の中での並び替えはできない

### F-06 サブタスク
- 一番下に追加する。50文字までで、空のときは追加しない
- 完了の切り替え、ドラッグでの並び替え、その場での書き直しができる。書き直して空にしたときは、元の文言に戻す
- 削除するときは確認を出さない
- タスク詳細に、完了した数と全体の数（例：1/3）を表示する
- ボードとダッシュボードのカードにも、同じ形（完了した数 / 全体の数）で表示する。サブタスクがないタスクには表示しない。スマホのカレンダーで、日付の下に出るタスクの一覧にも表示する。カレンダーのマスには表示しない（狭いため）

### F-07 期限アラート

| 表示 | 条件 |
|---|---|
| 黄 | 期限の3日前〜1日前 |
| 赤 | 期限の当日と、期限超過。当日のときは「期限当日」、期限超過のときは「期限超過」「見直しをしてください」も表示する |
| 表示しない | 期限がないタスク、完了ステータスのタスク |

- 「今日」は日本時間で判断し、朝4時に切り替わる（0時〜3時59分は前の日として扱う）
- アラートの色は、ダッシュボード、ボード、タスク詳細、カレンダーに表示する
- アラートの文言は「期限超過」「期限当日」「期限が近い」（3日前〜1日前）の3つ。ダッシュボード、タスク詳細、スマホのカレンダーの一覧（日付の下に出るタスクの一覧）に表示する。ボードのカードには「期限超過」だけを表示する
- 「見直しをしてください」は、ダッシュボードとタスク詳細にだけ表示する
- カレンダーのマスには、文言を表示しない（ボードのカードとカレンダーのマスは狭いため）
- スマホのカレンダーの一覧では、完了したタスクに「完了」と表示する

### F-08 ダッシュボード
- **今日やるタスク:** 今日選んだ、完了していないタスクを、選んだ順に表示する。朝4時を過ぎると自動で外れ、完了にするとすぐ外れる。完了から未完了に戻しても、今日やるタスクには戻らない（もう一度選び直す）
- **タスク一覧:** 全プロジェクトの、完了以外のタスクを表示する。今日やるタスクに選んだものは出さない
- **並び順:** 期限が近い順（期限超過が先頭）。期限が同じ日のタスクは、作成した順。期限のないタスクはその後ろに、作成した順で並べる

### F-09 カレンダー
- プロジェクトごとに、月表示で、期限の日にタスクを表示する。前の月・次の月・今月に切り替えられる
- 完了したタスクはグレーで表示し、期限のないタスクは表示しない
- PCではマスにタイトルを出し、長いものは省略する。スマホでは色の印だけを出し（アラートがあればその色、完了はグレー、それ以外はアプリの基本色）、日付を押すとその日のタスクを一覧で出す。一覧のカードには、サブタスクの数（完了した数 / 全体の数）も出す
- カレンダーを開くたびに、今月を表示し、今日を選んだ状態から始める（タブを切り替えたときや、ほかの画面から戻ったときも同じ。ダイアログを閉じただけのときは、そのまま）
- スマホで月を切り替えたときは、その月の1日を選んだ状態にする。今月に戻ったときは今日を選ぶ
- 今日の日付は、数字をアプリの基本色の丸で塗り、文字を白にする（PC・スマホ共通）。「今日」の判断は F-07 と同じ（日本時間で、朝4時に切り替わる）
- スマホで選択中の日付は、アプリの基本色の枠線の丸で表す。今日を選んでいるときは、塗った丸のまま
- タスクを押すと、タスク詳細を開く

### F-10 タスク詳細
- 表示と編集を分ける。タスク詳細では内容を表示し、「編集」でタスク作成・編集を開く
- サブタスクだけは、タスク詳細の中で直接操作できる

## 3. ユースケース

アクターは「ユーザー」（ログインした利用者）の1種類とする。

### 3.2 ユースケース詳細

#### UC-01 ログインする
- **アクター:** ユーザー
- **前提条件:** ログインしていない。アカウントが初期データで用意されている
- **基本フロー:**
    1. ユーザーが、ログイン画面でメールアドレスとパスワードを入力し、「ログイン」ボタンを押す
    2. システムが、入力内容を確認する
    3. システムが、ダッシュボードを表示する
- **代替・例外フロー:**
    - メールアドレスかパスワードが空のときは、入力を促すメッセージを表示する
    - メールアドレスかパスワードが間違っているときは、「メールアドレスまたはパスワードが正しくありません」と表示する
- **事後条件:** ログインした状態でダッシュボードが表示されている

#### UC-02 ログアウトする
- **アクター:** ユーザー
- **前提条件:** ログインしている
- **基本フロー:**
    1. ユーザーが、サイドメニューの「ログアウト」を押す
    2. システムが、ログイン状態を解除する
    3. システムが、ログイン画面を表示する
- **代替・例外フロー:** なし
- **事後条件:** ログアウトした状態で、ログイン画面が表示されている

#### UC-03 プロジェクトを作成する
- **アクター:** ユーザー
- **前提条件:** ログインしている
- **基本フロー:**
    1. ユーザーが、サイドメニューの「プロジェクトを追加」を押す
    2. システムが、プロジェクト作成ダイアログを表示する
    3. ユーザーが、タイトルを入力して保存する
    4. システムが、プロジェクトを保存し、初期ステータス「未着手 / 進行中 / 確認中 / 完了」を作り、未着手と完了のIDを記録する
    5. システムが、サイドメニューにプロジェクトを追加し、そのボード画面を表示する
- **代替・例外フロー:**
    - タイトルが空のときは、「タイトルを入力してください」と表示して保存しない
    - キャンセルしたときは、何も保存せずにダイアログを閉じる
- **事後条件:** 新しいプロジェクトがサイドメニューに表示され、4つの初期ステータスを持っている

#### UC-04 プロジェクトの名前・色を変更する
- **アクター:** ユーザー
- **前提条件:** プロジェクト設定画面を開いている
- **基本フロー:**
    1. ユーザーが、プロジェクト名を変える、または色を基本カラーから選ぶかカラーコードで指定して、保存する
    2. システムが、変更を保存する
    3. システムが、サイドメニューとプロジェクト画面の表示を変更後の名前と色に変える
- **代替・例外フロー:**
    - プロジェクト名が空のときは、エラーを表示して保存しない
    - カラーコードの形式が正しくないとき（例：`#` がない、桁が足りない）は、エラーを表示して保存しない
- **事後条件:** 変更後の名前と色が表示されている

#### UC-05 プロジェクトを削除する
- **アクター:** ユーザー
- **前提条件:** プロジェクト設定画面を開いている
- **基本フロー:**
    1. ユーザーが、「プロジェクトを削除」ボタンを押す
    2. システムが、「プロジェクトと、その中のタスクがすべて削除されます。よろしいですか？」と確認する
    3. ユーザーが、「削除」を押す
    4. システムが、プロジェクトと、その中のステータス・タスク・サブタスクを削除する
    5. システムが、ダッシュボードを表示する
- **代替・例外フロー:**
    - 確認で「キャンセル」を押したときは、削除しない
- **事後条件:** プロジェクトがサイドメニューから消えている

#### UC-06 ステータスを追加する
- **アクター:** ユーザー
- **前提条件:** プロジェクト設定画面を開いている
- **基本フロー:**
    1. ユーザーが、「ステータスを追加」を押し、ステータス名を入力して保存する
    2. システムが、ステータスを一番後ろに追加して保存する
    3. ボードに、新しい列が表示される
- **代替・例外フロー:**
    - ステータス名が空のときは、エラーを表示して保存しない
- **事後条件:** ボードに新しいステータスの列が表示されている

#### UC-07 ステータスを編集・並び替える
- **アクター:** ユーザー
- **前提条件:** プロジェクト設定画面を開いている
- **基本フロー:**
    1. ユーザーが、ステータス名を変える、または並び順を変えて保存する
    2. システムが、変更を保存する
    3. ボードの列の名前と順番が、変更後のものになる
- **代替・例外フロー:**
    - ステータス名が空のときは、エラーを表示して保存しない
- **事後条件:** ボードに、変更後の名前と順番で列が表示されている

#### UC-08 ステータスを削除する
- **アクター:** ユーザー
- **前提条件:** プロジェクト設定画面を開いている
- **基本フロー:**
    1. ユーザーが、ステータスの「削除」を押す
    2. システムが、「このステータスを削除しますか？」と確認する
    3. ユーザーが「削除」を押す
    4. システムが、ステータスを一覧から消す
    5. ユーザーが、プロジェクト設定の「保存」を押す
    6. システムが、ステータスを削除する
- **代替・例外フロー:**
    - ステータスにタスクが残っているときは、「保存」を押した時点で「タスクが残っているため削除できません」と表示し、何も保存しない
    - 「保存」を押さずに「キャンセル」で閉じたときは、削除しない
    - 初期ステータス（未着手）と完了ステータスは削除できない（削除ボタンを表示しない）
    - 確認で「キャンセル」を押したときは、削除しない
- **事後条件:** ボードからその列が消えている

#### UC-09 タスクを作成する
- **アクター:** ユーザー
- **前提条件:** ログインしていて、プロジェクトのボード画面を開いている
- **基本フロー:**
    1. ユーザーが、「タスクを追加」ボタンを押す
    2. システムが、タスク作成ダイアログを表示する
    3. ユーザーが、タイトル（必須）、説明、期限、ステータスを入力して保存する
    4. システムが、タスクを保存し、ボードの該当する列にカードを表示する
- **代替・例外フロー:**
    - タイトルが空のときは、「タイトルを入力してください」と表示して保存しない
    - キャンセルしたときは、何も保存せずにダイアログを閉じる
- **事後条件:** 新しいタスクがボードに表示されている

#### UC-10 タスクを編集する
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いている
- **基本フロー:**
    1. ユーザーが、「編集」ボタンを押す
    2. システムが、いまの内容が入った編集ダイアログを表示する
    3. ユーザーが、内容を変えて保存する
    4. システムが、変更を保存し、タスク詳細に戻る
- **代替・例外フロー:**
    - タイトルを空にしたときは、エラーを表示して保存しない
    - キャンセルしたときは、変更を保存せずにタスク詳細へ戻る
- **事後条件:** 変更した内容がボードとタスク詳細に表示されている

#### UC-11 タスクを削除する
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いている
- **基本フロー:**
    1. ユーザーが、「削除」ボタンを押す
    2. システムが、「このタスクを削除しますか？」と確認する
    3. ユーザーが「削除」を押す
    4. システムが、タスクとそのサブタスクを削除し、ダイアログを閉じる
- **代替・例外フロー:**
    - 確認で「キャンセル」を押したときは、削除しない
- **事後条件:** ボード・ダッシュボード・カレンダーからタスクが消えている

#### UC-12 タスクのステータス・並び順を変更する
- **アクター:** ユーザー
- **前提条件:** プロジェクトのボード画面を開いている
- **基本フロー:**
    1. ユーザーが、カードを別のステータスの列、または同じ列の別の位置へドラッグ＆ドロップする
    2. システムが、タスクのステータスと並び順を更新して保存する
    3. カードが、移した先の列と位置に表示される
- **代替・例外フロー:**
    - 保存に失敗したときは、カードを元の列と位置に戻してエラーを表示する
    - スマホではドラッグしにくいため、タスク編集からステータスを変えることもできる
    - 完了ステータスへ移したタスクは、今日やるタスクからすぐ外れる
- **事後条件:** タスクが新しい列と位置に表示されている

#### UC-13 サブタスクを追加する
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いている
- **基本フロー:**
    1. ユーザーが、サブタスクの入力欄に内容を入力し、追加する
    2. システムが、サブタスクを一番下に追加して保存する
- **代替・例外フロー:**
    - 内容が空のときは、追加しない
- **事後条件:** タスク詳細に新しいサブタスクが表示され、タスク詳細とカードのサブタスクの数（全体の数）が増えている

#### UC-14 サブタスクを完了にする
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いていて、サブタスクがある
- **基本フロー:**
    1. ユーザーが、サブタスクのチェックボックスを押す
    2. システムが、サブタスクの完了・未完了を切り替えて保存する
- **代替・例外フロー:**
    - 完了済みのサブタスクをもう一度押したときは、未完了に戻す
- **事後条件:** サブタスクの完了状態が切り替わり、タスク詳細とカードのサブタスクの数（完了した数）が変わっている

#### UC-15 サブタスクを並び替える
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いていて、サブタスクが2つ以上ある
- **基本フロー:**
    1. ユーザーが、サブタスクをドラッグして順番を変える
    2. システムが、新しい並び順を保存する
- **代替・例外フロー:**
    - 保存に失敗したときは、元の順番に戻してエラーを表示する
- **事後条件:** サブタスクが新しい順番で表示されている

#### UC-16 サブタスクを編集する
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いていて、サブタスクがある
- **基本フロー:**
    1. ユーザーが、サブタスクの文言をクリックして書き直す
    2. システムが、変更を保存する
- **代替・例外フロー:**
    - 文言を空にしたときは、保存せずに元の文言に戻す
- **事後条件:** 書き直した文言が表示されている

#### UC-17 サブタスクを削除する
- **アクター:** ユーザー
- **前提条件:** タスク詳細を開いていて、サブタスクがある
- **基本フロー:**
    1. ユーザーが、サブタスクの「削除」を押す
    2. システムが、サブタスクを削除する
- **代替・例外フロー:** なし
- **事後条件:** タスク詳細からサブタスクが消え、タスク詳細とカードのサブタスクの数が減っている。サブタスクが0件になったら、カードには数を表示しない

#### UC-18 期限アラートを確認する
- **アクター:** ユーザー
- **前提条件:** ログインしていて、期限が設定されたタスクがある
- **基本フロー:**
    1. ユーザーが、ダッシュボードまたはボードを開く
    2. システムが、今日の日付（日本時間。朝4時に切り替わる）と各タスクの期限を比べる
    3. システムが、期限の3日前〜1日前のタスクを黄色、当日と期限超過のタスクを赤で表示する
    4. システムが、期限当日のタスクに「期限当日」、期限超過のタスクに「期限超過」「見直しをしてください」と表示する（表示する画面は F-07 のとおり）
- **代替・例外フロー:**
    - 完了ステータスのタスクには、アラートを表示しない
    - 期限が設定されていないタスクには、アラートを表示しない
- **事後条件:** 期限が近いタスクと過ぎたタスクが、色で見分けられる

#### UC-19 今日やるタスクを選ぶ
- **アクター:** ユーザー
- **前提条件:** ダッシュボードを開いている
- **基本フロー:**
    1. ユーザーが、右側のタスク一覧から、左側の「今日やるタスク」へタスクを移す
    2. システムが、そのタスクを今日やるタスクとして保存する
- **代替・例外フロー:**
    - スマホでは、タスクの「今日やる」ボタンでも移せる
    - 朝4時を過ぎて日付が変わると、前の日に選んだタスクは自動で今日やるタスクから外れる
    - タスクを完了にすると、今日やるタスクからすぐ外れる
- **事後条件:** タスクが「今日やるタスク」に表示されている

#### UC-20 今日やるタスクから外す
- **アクター:** ユーザー
- **前提条件:** ダッシュボードの「今日やるタスク」にタスクがある
- **基本フロー:**
    1. ユーザーが、タスクの「外す」ボタンを押す
    2. システムが、今日やるタスクから外して保存する
- **代替・例外フロー:** なし
- **事後条件:** タスクが「今日やるタスク」から消え、タスク一覧に表示されている

#### UC-21 カレンダーで期限を確認する
- **アクター:** ユーザー
- **前提条件:** プロジェクト画面を開いている
- **基本フロー:**
    1. ユーザーが、「カレンダー」タブを押す
    2. システムが、今月のカレンダーを表示し、期限日の位置にタスクを表示する。今日の日付には印をつける
    3. ユーザーが、前の月・次の月へ切り替える
    4. ユーザーがタスクをクリックすると、システムがタスク詳細を表示する
- **代替・例外フロー:**
    - 期限が設定されていないタスクは、カレンダーに表示しない
    - 完了したタスクは、グレーで表示する
- **事後条件:** 期限ごとのタスクの並びを確認できる
